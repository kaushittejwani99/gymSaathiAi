GymSaathi — QR AI Registration Assistant + Automatic Attendance
==============================================================

Requested first-scan experience
-------------------------------
When a QR link is opened on a device without a saved, valid member session, the page now opens a conversational AI registration assistant rather than showing a blank/default form. It asks one question at a time, shows text chat, supports microphone transcription in compatible browsers, and speaks assistant prompts where browser speech synthesis is available.

Flow
----
1. Each gym has its own QR token and public registration/check-in URL.
2. A first scan without a valid device cookie opens the AI assistant if at least one membership plan has a configured price.
3. The assistant asks for the full name and mobile first. The site checks those against the current gym only. If they match an existing member, it verifies the existing record, marks attendance only if membership is active, sets the remembered-device cookie, and does not create a duplicate or ask the remaining registration questions.
4. If the name/mobile do not match an existing same-gym member, the assistant continues through registration. Optional fields may be skipped; available membership plans and calculated fee are reviewed before the user confirms.
5. Public self-registration always records ₹0 paid. Payment is not taken or recorded by the public QR flow. A new member and membership are saved to the gym's database; attendance is recorded if the membership is active today, and the HttpOnly gym-scoped cookie is issued.
6. On the next scan in the same browser, the saved cookie identifies the member with no name/mobile prompt. Membership dates are rechecked every time. An active member gets attendance; same-day duplicate scans do not create another row; inactive/expired/future-start memberships do not get attendance.
7. Dashboard attendance shows a visible “✓ Present” status, member name, mobile and check-in time.

Implementation and safety changes
---------------------------------
- `server.js`: added a rate-limited public `/assistant-turn` endpoint that calls the existing registration dialogue; it deliberately passes no member list to an unauthenticated assistant request. Public registration saves weight, height and health fields when supplied. Final registration checks the submitted same-gym phone/name again to prevent duplicates.
- `lib/ai.js`: adapted registration questions for a public member, supports natural Hindi self-introductions in local fallback, and treats any valid priced membership plan (not only the one-month price) as sufficient for registration.
- `public/join.html`, `public/join.js`, `public/join.css`: chat-first QR page; text and microphone entry; assistant prompts may be spoken aloud; optional skip; existing-member recognition after name/mobile; review card before saving; success and automatic repeat-scan feedback.
- `public/app.js`: Settings QR explanation states that first scan opens the AI registration assistant; dashboard retains per-member “✓ Present” name/mobile/time rows.
- Public assistant output does not include a member list or private payment/member records. Cookie secrets remain HttpOnly, SameSite=Lax, path-scoped per gym QR route, random, and stored as hashes server-side.

Limitations / required staging validation
-----------------------------------------
These tests run against an isolated file-backed test database and local fallback logic. They do not prove live Render behavior, production MongoDB Atlas data, the real Gemini API, Meta WhatsApp messaging, or a real physical phone/camera scan. A Chromium browser smoke test was attempted but local Chromium blocked localhost navigation with `ERR_BLOCKED_BY_ADMINISTRATOR`, so no real visual-browser interaction is claimed. Deploy to a staging copy and test on a real phone before production rollout. Do not overwrite `.env` or production data; inspect `git diff` after applying the ZIP.

Security note
-------------
First-time existing-member recognition is still based on name + mobile matching, not OTP proof of phone ownership. A person who knows both could try to bind another device. For stronger identity assurance, add SMS/WhatsApp OTP or a staff-issued activation code.
